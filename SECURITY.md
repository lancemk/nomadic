# Security Policy

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub Issues or pull requests.

Use a private reporting path instead:

1. Use GitHub private vulnerability reporting for this repository if it is enabled.
2. If private reporting is not available, contact the maintainer account for this repository on GitHub and include `nomadic security report` in the subject or opening line.

## What to Include

Please include as much of the following as possible:

- a clear description of the issue
- affected versions or commit range, if known
- reproduction steps or proof of concept
- impact assessment
- any relevant environment, configuration, or deployment details
- whether the issue is already known publicly

## Disclosure Guidelines

- Do not open a public issue for a suspected vulnerability.
- Do not post exploit details in pull requests, discussions, or issue comments.
- Give maintainers reasonable time to assess and address the report before public disclosure.

## Response Expectations

Maintainers will make a best effort to acknowledge reports promptly, assess severity, and coordinate remediation. Response times are goals rather than guaranteed service levels.
